# Комментарии в коде

Требование к тому, кто меняет этот репозиторий — человеку или агенту: комментарий объясняет
**почему**, а не **что**. Краткая версия живёт в `AGENTS.md` (раздел `### Комментарии в коде`);
здесь — приёмы, формулировки запроса и примеры «почему»-комментариев, уже существующих в проекте.

## Что комментировать

«Что»-комментарий пересказывает код (`// создаём массив`, `// проверяем валидность токена`) и не
добавляет ничего: и человек, и агент видят это из самого кода, из соседних модулей, тестов и
`git log`. Ценность несёт то, чего в коде нет:

- **ограничение внешней системы** — «API отдаёт 429 при более чем 10 запросах в секунду»;
- **обходной путь** — «прямой вызов не работает из-за бага в версии 2.3, разбиваем вручную»;
- **требование бизнеса** — «округление вниз по требованию бухгалтерии вместо математического»;
- **осознанно выбранный «простой» вариант** — там, где очевидный «правильный» ломает рабочее
  решение.

Пример, который без комментария выглядит как кандидат на улучшение:

```ts
// Retry с фиксированной задержкой 2 c. Exponential backoff здесь не подходит:
// провайдер блокирует клиента при запросах чаще раза в секунду, но требует
// повтора в течение 5 секунд после ошибки.
async function processPayment(order: Order) {
  for (let attempt = 0; attempt < 3; attempt++) {
    // ...
  }
}
```

Так же выглядят `SAFE_BATCH_SIZE = 50` без объяснения (число кажется произвольным — его
предложат увеличить или вынести в конфиг) и последовательная обработка там, где просится
параллельная. Комментарий вида `// sequential вместо parallel: rate limit у платёжного
провайдера` сохраняет это ограничение при любой последующей правке.

## Комментарий как лакмус

Если причину решения не удаётся изложить в одном-двух предложениях — это сигнал, что код делает
слишком много или его структура неочевидна. Сначала упростить или разбить, потом комментировать.

## Как просить агента

Просьба «добавь комментарии к файлу» по умолчанию даёт пересказ кода. Работает формулировка
**«добавь комментарии, объясняющие причины принятых решений и ограничения, влияющие на
реализацию»**: агент идёт в `git log`/`blame`, связанные тесты и issue и восстанавливает контекст.

Сгенерированный комментарий — **черновик**. Агент может приписать коду мотивы, которых у автора
не было, или пропустить настоящую причину. Неверный комментарий хуже отсутствующего: он вводит в
заблуждение и следующего агента, и человека. Каждый такой комментарий проверяет автор изменения —
сверкой с историей и тестами, а не догадкой.

## Зачем это агенту

Каждая сессия начинается с чистого контекста: агент читает код заново и делает выводы из того,
что видит. «Почему»-комментарий — единственное, что переживает границу сессии. Без него
повторяется один и тот же цикл: убрать «лишнюю» проверку, упростить обходной путь, заменить
«медленный» подход на «правильный». Вместе с типами (верифицируемый контекст о структуре данных)
комментарии формируют слой, который делает каждую следующую задачу точнее.

## Примеры в этом репозитории

Так уже сделано в `src/` — это эталон для нового кода:

- `src/proxy.ts:12` — зачем нужен `RATE_MAP_MAX`: без него карта растёт на одну запись на каждый
  новый IP, «медленная утечка на коробке с ~800 МБ, которая никогда не перезапускается».
- `src/proxy.ts:17` — почему `sweepExpired` чистит только истёкшие окна: сброс всего на таймере
  выдаёт нарушителю новый лимит.
- `src/lib/ffmpeg.ts:9` — почему ffmpeg-обвязка вынесена в отдельный модуль: иначе
  `withFfmpegSlot` перестаёт быть единственной глобальной очередью, а прод-VPS имеет 1 ядро.
- `src/lib/ffmpeg.ts:75` — почему постер снимается на 33% длительности, а не нулевым кадром:
  нулевой часто оказывается чёрным или логотипом.
- `src/app/api/video-stream/route.ts:9` — почему видео отдаётся нативным `<video>`, а не
  сгенерированным «трейлером»: меньше движущихся частей против байтов по сети — обмен, принятый
  ради той же одноядерной коробки.
- `src/app/page.tsx:101` — почему `useSyncExternalStore`, а не ленивый инициализатор
  `useState`: иначе серверная разметка «masonry/light» гидрируется значением из хранилища и
  ловится hydration mismatch.
- `src/app/page.tsx:463` — почему загрузчики трогают state только в `then`-колбэках: синхронный
  `setIsLoading` в эффекте — ровно тот setState-in-effect, который починили в #12.

## Правила репозитория

- Комментарии в коде — английский: весь `src/` написан так, а смесь языков внутри файла дороже,
  чем один выбранный. Русский — в UI-строках (см. `AGENTS.md`, `## Conventions`).
- Чужой «почему»-комментарий сохраняется при правке соседнего кода: это чья-то реконструкция
  причины, а не мусор. Устаревший — поправь по факту, а не походя.
