# ADR 0002: Гибридный трекинг задач — `ai/tasks` + GitHub Issues

## Status

Accepted — 2026-09-28.

## Context

В проекте уже есть собственный AI-цикл: `ai/inbox.md` → `.agents/skills/process-inbox` →
`ai/tasks/<date>/<slug>/` (`task.md` + `state.yaml`) → `.agents/skills/perform-task` →
`.agents/skills/continue`. Он хорошо работает для мелких, локальных задач одного мейнтейнера.

В проекте-доноре (`ai-for-developers-project-386`) все задачи обязаны проходить через
GitHub Issues с triage-метками. При переносе харнеса встал вопрос: дублировать системы
нельзя, а Issues дают видимый backlog, метки и кросс-ссылки на коммиты.

## Decision

Гибрид:

- **Мелкое и механическое** (≤ ~2 файлов, без публичного API/UX) → `ai/inbox.md` → `ai/tasks/`,
  как раньше. Плюс правило: мелкие/механические правки можно делать без Issue.
- **Крупные фичи, баги и всё, что меняет публичный API/UX или формат `.data`** → GitHub Issue
  (`gh issue create`, метки из `docs/agents/triage-labels.md`), номер указывается в коммите
  (`(#NN)`), после пуша Issue закрывается.
- Разделение зафиксировано в `AGENTS.md` → «Agent behavior»; маршрутизация описана в
  `process-inbox/SKILL.md`.

## Consequences

(+) Нет двойного учёта: у каждой задачи ровно один дом.
(+) Крупные вещи видны в Issues (backlog, метки, ссылки), мелкие не засоряют трекер.
(+) Локальный цикл не переписывается — уже работающие скиллы остаются.
(−) Два места, где может лежать задача: нужна дисциплина маршрутизации (правило в скилле
и AGENTS.md), иначе мелочь уедет в Issues.
(−) Требуется авторизованный `gh` на машине мейнтейнера для крупных задач.

## Alternatives considered

- **Только GitHub Issues** (как в 386) — переписывает работающий цикл, завязывает мелочь на
  сеть и `gh`, ломает `ai/tasks`-историю.
- **Только `ai/tasks`** — крупные фичи не видны снаружи, нет меток/приоритетов, нет
  удобной связи «коммит ↔ задача» для багов.
- **Issues для всего** — трекер засоряется опечатками и однострочниками.
