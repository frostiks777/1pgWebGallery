# ADR 0004: Агент в GitHub Actions: `/oc`, автотриаж, ревью, регулярный аудит

## Status

Accepted — 2026-10-13.
Amended — 2026-10-15: модель вынесена в Variable `OPENCODE_MODEL`, таймаут авторевью поднят
до 20 минут (см. «Обновление 2026-10-15»).
Amended — 2026-10-15 (второе): `small_model` приравнена к основной модели, служебная модель
opencode больше не вызывается (см. «Обновление 2026-10-15 (второе)»).
Amended — 2026-10-27: провайдер CI — Google AI Studio (`google/*`, секрет `GEMINI_API_KEY`),
субагенты больше не пинят модель в `opencode.jsonc` (см. «Обновление 2026-10-27»).
Решение о самих воркфлоу остаётся в силе.

## Context

До этого репозиторий знал агента только в терминале: `interview → plan → verify → commit-push`
локально, задачи — в `ai/tasks/` и в GitHub Issues вручную. Разбор новой задачи, ревью PR и
регулярная проверка состояния проекта целиком зависели от того, что Андрей сидит за ноутбуком.

Набор воркфлоу взят из проекта-донора
[`ai-for-developers-project-387`](https://github.com/frostiks777/ai-for-developers-project-387)
(курс «ИИ для разработчиков», шаги 2–6): ручной вызов из комментария, автотриаж новых issue,
авторевью PR и регулярный аудит по расписанию. Механизм — GitHub App `opencode-agent`
(обмен OIDC-токена на токен приложения, `id-token: write`) и экшен
`anomalyco/opencode/github@latest`, модель `opencode/mimo-v2.6-flash-free` — та же бесплатная,
что в `opencode.jsonc`.

Что пришлось решить по месту, а не скопировать:

- **Аудит.** В доноре это Lighthouse по стенду на Render. Здесь единственный машинный сигнал о
  состоянии кода — вывод `eslint`/`tsc`, а прод — https://ap-p-g.duckdns.org/ с опциональным
  паролем на `WEBDAV_LOGON_PASSWORD` (замер может упереться в экран пароля). Решено: два
  независимых источника (проверки репозитория + Lighthouse по `APP_URL` из Variables), один
  разбор агентом.
- **Baseline.** На момент решения он пустой: `npx eslint .` и `npx tsc --noEmit` проходят
  чисто (ошибки `react-hooks/set-state-in-effect` и TS2345 в `video-stream/route.ts` починены
  коммитами `8a922af` и `4370e29`). Поэтому проверки в аудите не роняют прогон — их вывод всё
  равно уходит в отчёт и в разбор агента, — а промпт прямо говорит: любая ошибка линтера или
  типов это новая находка. Блокирующая проверка остаётся в `ci.yml`; дублировать её в аудите
  незачем.
  Отдельно в промпте оговорено, что не считать находкой два проектных ограничения:
  необходимость исходящего HTTPS к Google Fonts у `next build` и невозможность гонять e2e
  локально.
- **Деплой.** Пуш в `main` здесь означает rsync на прод (`deploy.yml`), в отличие от донора.
  Интерактивный воркфлоу оставлен с `contents: write` (иначе агент не сможет открыть PR по
  `/oc исправь`), а запрет пушить в `main` передан агенту текстом. **Этого недостаточно:**
  эндпоинту «Merge a pull request» по документации GitHub достаточно `contents: write`,
  то есть токен раннера в этом воркфлоу технически может слить PR через `gh pr merge`.
  Надёжная защита — branch protection на `main` («Require a pull request before merging»),
  и её нужно включить руками; до этого момента текстовый запрет — единственный барьер.
- **Триаж и ревью.** Промпты переписаны под этот репозиторий: реальные пути
  (`src/app/page.tsx`, `src/components/gallery/`, `src/proxy.ts`, `.data/`), реальные скиллы
  (`.agents/skills/interview`, `plan`) и реальные правила из `AGENTS.md` (русские строки, префикс
  `obs-`, `bunx`, Conventional Commits). В доноре промпт ссылался на скилл
  `plan-small-feature`, которого здесь нет.

## Decision

В `.github/workflows/` добавлены четыре воркфлоу:

| Файл | Событие | Права | Что делает |
|---|---|---|---|
| `opencode.yml` | `issue_comment`, `pull_request_review_comment` (`created`) | `contents/pull-requests/issues: write`, `id-token: write` | ручной вызов `/oc` или `/opencode` |
| `opencode-triage.yml` | `issues` (`opened`) | `contents: read`, `issues: write`, `id-token: write` | разбор новой задачи комментарием |
| `opencode-review.yml` | `pull_request` (`opened`/`synchronize`/`reopened`/`ready_for_review`) | `contents: read`, `pull-requests: write`, `id-token: write` | замечания к PR |
| `opencode-audit.yml` | `schedule` (`17 6 * * *`) + `workflow_dispatch` | `contents/pull-requests/issues: write`, `id-token: write` | `eslint`/`tsc` + Lighthouse → issue |

Общие решения по всем четырём:

- `id-token: write` везде, `share: false` явно (дефолт opencode для публичного репозитория —
  `share: true`, а в сессии видны вывод команд и код);
- фильтр событий от ботов (`sender.type`/`user.type != 'Bot'`), в интерактивном воркфлоу —
  ещё и `author_association` (владелец/участник/контрибьютор/контрибьютор);
- `timeout-minutes` 15–20 и `concurrency` с `cancel-in-progress`, чтобы агент не держал раннер
  до 360 минут и не наслаивал прогоны;
- `persist-credentials: false` везде, кроме интерактивного воркфлоу: там он нужен, иначе
  `git push` агента падает с «could not read Username»;
- модель `opencode/mimo-v2.6-flash-free`, ключ — в секрете `OPENCODE_API_KEY`;
- адрес стенда — в Variable `APP_URL`, не в файле.

`ci.yml` и `deploy.yml` не тронуты. Аудит не дублирует `ci.yml`: `ci.yml` блокирует сборку,
аудит — только заводит задачи.

## Consequences

(+) Разбор задачи, ревью PR и регулярная проверка перестали зависеть от того, что Андрей
за компьютером; следы работы видны в Actions и Issues.
(+) Аудит даёт регулярный машинный сигнал о коде: любая ошибка линтера или типов попадает
  в issue, а не теряется до следующего локального прогона.
(+) Адрес стенда в Variable — переезд прода не требует правки воркфлоу и коммита.
(+) `audit-report/`-артефакты (30 дней) + step summary дают историю замеров.
(−) Каждый вызов агента тратит минуты Actions и лимит бесплатной модели. Отсюда `timeout`,
`concurrency`, фильтр ботов, узкий круг вызывающих и «не больше двух issue за прогон».
(−) `/oc исправь` даёт агенту `contents: write` — единственное место в наборе, где агент может
коммитить. Защита от пуша в `main` текстовая, а не техническая: токен раннера не умеет merge,
но push в ветку `main` технически возможен, если промпт нарушит запрет.
(−) `opencode-review.yml` пропускает PR, открытые ботом. Следствие: PR от агента (бот) не
ревьюится автоматически — это осознанный размен минут Actions на отсутствие саморевью.
(−) Регулярный аудит добавляет до ~35 минут Actions в сутки.
(−) Расходы: у бесплатной модели есть дневной лимит запросов. Плановый аудит в 06:17 UTC может
исчерпать его и оставить ручные вызовы без ответа.

## Alternatives considered

- **Только `opencode.yml` (ручной вызов).** Дёшево по минутам Actions, но разбор задач и ревью
  остаются ручными — то есть ничего не меняется по сравнению с сегодня.
- **Аудит только по коду (без Lighthouse).** Отказ от замера прода: доступность и
  производительность в этом проекте не измеряются нигде, а именно на них жалуются гости.
- **Аудит только по Lighthouse.** Не ловит регрессии в коде — единственный машинный сигнал
  проекта (eslint/tsc) был бы не задействован.
- **Запуск `npm run test:e2e` в аудите.** Отклонено: в CI он требует Chromium и поднятого
  `next dev`. (Поправка 2026-10-15: в исходной формулировке отклонение опиралось на «e2e
  локально не гоняем» — это было неверно, тесты работоспособны, см. `checks.md`. Причина
  отклонения остаётся прежней: стоимость раннера, а не неработоспособность e2e. Пункт о
  возврате e2e в CI открыт в #13.)
- **Другая модель в воркфлоу.** Отклонено в пользу той же, что в `opencode.jsonc`, иначе
  агент в CI и агент в терминале будут вести себя по-разному.

## Обновление 2026-10-15: модель в Variable, таймаут авторевью 20 минут

Через два дня после принятия ADR ревью на PR #28 не оставило замечаний: прогон
`38609684894` упёрся в `timeout-minutes: 15` и был отменён. Первая версия разбора
этого лога оказалась неверной, поэтому здесь итог — вместе с тем, что в него
не входит.

Что в логе на самом деле:

```
17:48:27  modelID: "gpt-5.4-nano"
          AI_APICallError: Model access is disabled (isRetryable: false)
17:49:29  modelID: "mimo-v2.6-flash-free"     ← основная модель работает
...
18:01:45  msg_13b93cfa… → git → новый stream   ← агент РАБОТАЛ
18:03:06  ##[error]The operation was canceled.  ← за 81 секунду до конца
```

1. **`Model access is disabled` не относится к модели воркфлоу.** Ошибка приходит от
   служебной модели opencode — он подставляет свою для заголовка сессии. Основная
   модель после неё работает, и та же ошибка встречается в **успешных** прогонах.
   На таймаут это не влияет. Что с ней делать — см. «Обновление 2026-10-15 (второе)»
   ниже: в первом разборе она была названа шумом, который не нужно обходить, и
   это оказалось неверно.
2. **Агент не зависал.** Он делал новые вызовы модели за секунды до отмены. Ревью
   большого диффа просто не укладывается в 15 минут.

Что решили:

- **Таймаут авторевью 15 → 20 минут.** Единственная правка таймаута в этом обновлении:
  наблюдался реальный недобор времени, сокращать лимит было бы ошибкой.
- **Модель — в Variable `OPENCODE_MODEL`** во всех четырёх воркфлоу, а не строкой в
  каждом. Смена модели сейчас требует правки четырёх файлов, а бесплатные модели
  отключаются провайдером регулярно. Пустое значение проверяется явным шагом: иначе
  `opencode/` уехал бы молча на модель по умолчанию. Текущее значение — в настройках
  репозитория, в коде оно намеренно не зашито.
- **Аргумент «та же модель, что в терминале» перестал работать.** Он записан в
  «Alternatives considered» выше. Отключение модели в CI не должно требовать менять
  `opencode.jsonc`: терминал и Actions могут смотреть на разные модели.
- **Таймауты триажа (15) и разбора аудита (20) не тронуты** — недобора времени на них
  не наблюдалось, менять нечего.
- **Авторевью при падении агента оставляет комментарий в PR** со ссылкой на прогон. Job
  при этом остаётся красным: зелёный чек при отсутствии замечаний вводил бы в заблуждение.

Чего правка не делает: при срабатывании `timeout-minutes` на уровне job оставшиеся
шаги не выполняются. Поэтому при **таймауте** (а это и был исходный случай на PR #28)
комментарий не появится — только красный крест. Шаг ловит быстрые падения агента, а не
недобор времени. Сделать таймаут пошаговым в Actions нельзя.

## Обновление 2026-10-15 (второе): служебная модель opencode

Первое обновление записало `Model access is disabled` как «шум провайдера, чинить и
обходить его не нужно». Формулировка была неверной хотя бы потому, что такой шум
сбивает с толку: именно из-за него в #40 принят неверный диагноз (решено, что
провайдер отключил основную модель, и на этом основании чуть не урезали таймаут).

Разобраться пришлось точнее. Ошибка приходит не от основной модели воркфлоу, а от
служебной: opencode подставляет свою для **заголовка сессии** (агент `title`), и
дефолтный дешёвый вариант у провайдера отключён. Основная модель после ошибки
работает, прогон завершается успешно.

Что решили:

- **`small_model` в `OPENCODE_CONFIG_CONTENT` приравнен к основной модели воркфлоу.**
  Служебный вызов уходит туда же, где доступ точно есть, и ошибка из лога исчезает.
- **Правка ограничена CI.** `opencode.jsonc` общий с локальными сессиями терминала,
  а `OPENCODE_CONFIG_CONTENT` — inline-конфиг с наивысшим приоритетом, который
  мержится с проектным, а не заменяет его. Терминал не затрагивается.
- **Комментарий при сбое в `opencode-review.yml` переписан.** Раньше он советовал
  отличать эту ошибку от настоящих поломок; после приравнивания ошибка в логе
  действительно указывает на основную модель, и совет стал бы вводить в заблуждение.

Честная цена решения, важная при следующем пересмотре: `small_model` — это агент
`title`, то есть каждая сессия начинается с полноценного вызова основной модели
вместо дешёвого. На бесплатной модели это незаметно, но «совсем не влияет на
поведение» — неверно.

Связанное: #40, #44.

## Обновление 2026-10-27: провайдер — Google AI Studio

2026-10-27 регулярный аудит упал с `401 Invalid credential` от
`https://opencode.ai/inference/openai/v1/chat/completions`. Проверка показала, что дело не в
модели и не в сети: локально та же модель отвечала, шлюз с валидным креденшелом отдавал `200`,
а с мусорным — ровно тот же `401`. То есть воркфлоу дошли до шлюза и были отвергнуты на
авторизации, а не потеряли провайдера.

Починить это заменой ключа было нельзя: доступ к OpenCode Console у владельца пропал. Плюс
выяснилось ограничение, которое меняет оценку всего решения: **бесплатные модели `opencode/*`
шлюз обслуживает только самому OpenCode** — любому другому клиенту он отвечает `401`/`403`
даже с валидным ключом. Тот же класс отказа уже был в CI 2026-10-19 (`403 FreeTierError`,
«free models aren't available from your current network»), и тогда его списали на блокировку
по IP раннера. Вывод: бесплатный тир opencode как основа для CI — нестабильная опора, а не
рабочая модель с редкими сбоями.

Что решили:

- **Провайдер CI — Google AI Studio**, ключ в секрете `GEMINI_API_KEY` (переменная
  окружения, которую ждёт провайдер `google`), модель в воркфлоу — `google/${{ vars.OPENCODE_MODEL }}`.
  Значение `OPENCODE_MODEL` остаётся **без префикса**: префикс — часть воркфлоу, чтобы смена
  провайдера не требовала переписывать значение переменной.
- **Субагенты больше не пинят модель в `opencode.jsonc`.** Пин `opencode/nemotron-3.5-lightning-free`
  пережил бы смену провайдера внутри `explore`/`general` и уронил бы прогон уже после того, как
  основная модель починена — причём только на шагах, где агент решает позвать субагента.
  Без пина субагент наследует модель родительской сессии (документация opencode, «Model» в
  разделе агентов), и в CI это автоматически та же модель, что в `OPENCODE_MODEL`.
- **`small_model` остаётся приравненной к основной** — решение 2026-10-15 (второе) не меняется,
  меняется только префикс провайдера. В схеме v2 поле помечено `deprecated`, но работает;
  переписывать его на `agents.title` — отдельная правка, а не побочный эффект смены провайдера.
- **Локальные сессии не тронуты:** в `opencode.jsonc` по-прежнему `opencode/mimo-v2.6-flash-free`
  и `GEMINI_API_KEY` локально не нужен.

Отвергнутые варианты:

- **GitHub Models.** Закрыт 30.07.2026 целиком (playground, каталог, inference API, BYOK) —
  «бесплатный ключ GitHub» больше не выдаётся никому. Fine-grained PAT с `Contents: RW`
  открывает API репозитория, а не инференс; в этих воркфлоу он не нужен вовсе — авторизация в
  GitHub идёт через App `opencode-agent` и `GITHUB_TOKEN`.
- **GitHub Copilot.** Требует подписки Pro/Pro+ и интерактивного device-flow; статического
  ключа для CI у него нет. Обходное «засевание» OAuth-токена в секрет — неофициальный путь,
  который ломается на первой ротации.
- **OpenRouter.** Технически равноценен (ключ уже был), но выбран Google AI Studio.

Честная цена решения:

- **Квота.** Бесплатный тир Google ограничен по запросам в минуту и в сутки, а регулярный аудит
  и ревью больших диффов делают много вызовов. Упор в квоту выглядит как `429` /
  `RESOURCE_EXHAUSTED` — это не поломка кода, и лечится другой моделью или платным ключом.
- **Ключ не должен иметь ограничений по HTTP-реферреру или IP** — CI-раннер придёт с чужого
  адреса, и такой ключ даст `403`/`400`, неотличимые на глаз от «ключа нет».
- **Ключ AI Studio виден в консоли только при создании.** Потерянный ключ не «посмотреть
  ещё раз», а перевыпустить.

Связанное: #105 (смена провайдера), `docs/adr/0004`.
