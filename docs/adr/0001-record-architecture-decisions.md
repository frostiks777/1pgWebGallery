# ADR 0001: Record architecture decisions

## Status

Accepted — 2026-09-28.

## Context

Проект ведёт один мейнтейнер (Andrew), разработка идёт в том числе AI-агентами. Решения
принимаются в чате и теряются между сессиями; `AGENTS.md` фиксирует правила, но не историю
выбора. Перенос харнеса из проекта `ai-for-developers-project-386` принёс практику ADR —
лёгких записей об архитектурных решениях.

## Decision

Ведём `docs/adr/`: один файл = одно решение, по шаблону `template.md`, с индексом в
`README.md`. ADR пишется для трудно обратимых решений (формат `.data`, API-контракты,
деплой, зависимости с последствиями) и при выборе между альтернативами. Ссылки на ADR —
из `MEMORY.md` и `AGENTS.md`.

## Consequences

(+) История решений сохраняется между сессиями и не зависит от контекста чата.
(+) Агент перед трудно обратимым изменением читает релевантный ADR и явно фиксирует конфликт.
(−) Дисциплина: решение нужно описать и закоммитить отдельно, это замедляет мелкие правки.
(−) Риск дублирования с `MEMORY.md`, если писать ADR на каждую мелочь — поэтому в
`README.md` явно перечислено, когда ADR **не** нужен.

## Alternatives considered

- **Только `MEMORY.md`** — состояние да, история выбора нет; при обновлении «текущего
  состояния» прошлые решения затираются.
- **Комментарии в коде** — не видно из корня проекта, агент их не читает до погружения в файл.
- **Внешняя вики/Confluence** — лишний сервис для single-maintainer проекта.
